# 插件组合性能修复（2026-10-14）

> 这一篇只针对**当时那一次插件组合**的组合行为。之后做了面向**任意新增插件**的加载器/后端改造：
> 见 `docs/18-loader-scale.md`（并发下载、每插件超时隔离、惰性解压、发现缓存、逐插件遥测）。

当前组合：LyricBar 0.3.6、MaterialYouTheme v1.0.4、RefinedNowPlaying 3.0.2。

发现加载器在 `reloadPlugins()` 时重跑全部插件，但第三方插件没有完整的卸载接口，导致旧样式、React 实例、观察器与监听器留在页面。字体维护期间的多次热加载加重了这一问题。

`loader/framework.js` 现在每个页面仅执行一次插件加载链，后续刷新请求合并为一次页面刷新，由新文档重新加载全部插件。这样可以完整释放旧实例；插件管理与开发刷新会刷新页面，不再原地重复执行插件。

## 实机记录

数据来自同一客户端修复前、清理刷新后的快照；全部插件保持启用。

| 项目 | 修复前 | 修复后 |
|---|---:|---:|
| style 元素 | 192 | 42 |
| 重复 style 内容 | 149 | 3 |
| `.rnp-lyrics` 根节点 | 7 | 1 |
| 字体 CSS 字符数 | 88,613 | 12,229 |
| DOM 事件监听器（CDP） | 3,585 | 1,646 |
| JS 已用堆快照 | 75,389,408 B | 50,482,924 B |

原始记录：`out/perf-before.json`、`out/perf-after.json`，可通过 `node tools/perf_audit.mjs <label>` 采集。堆与监听器包括浏览器内其他文档，是快照而非长期峰值。4 秒后台 CPU 采样几乎全部为 idle，没有录到实际播放动画负载，不能据此声称帧率或 CPU 占用改善百分比。

## 回归

- `node test/plugin-reload.mjs`：多次/并发刷新请求不重复执行插件，合并为一次页面刷新。

没有关闭插件、修改用户动画/主题选项或重置字体配置。
